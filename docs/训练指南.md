# 模型训练与使用指南

> 面向：要让"智能工具检测系统"认出更多工具、解决摄像头漏检的人。
> 这份文档讲清楚 **为什么漏检**、**怎么在界面上一键训练**、**怎么采数据才有效**。

---

## 0. 先理解：为什么摄像头检测不出来某些工具

摄像头本身**不负责"认"工具**，它只是把画面一帧帧喂给模型。真正决定认不认得出的，是训练好的模型文件 **`data/yolo/best.pt`**——它的"知识"在训练完成那一刻就**冻结**了。

所以"摄像头检测不出某工具" = **这个工具在摄像头里的样子，模型训练时没见过（或见得太少）**。常见原因，按可能性排序：

| 原因 | 说明 | 解决 |
|---|---|---|
| **域差距（头号原因）** | 训练用手机近距离特写，摄像头是远距离/俯拍/杂乱背景，同一工具"长相"差太远 | 用**摄像头实际位置**采集训练素材 |
| 样本太少 | 某工具训练图太少，换个角度/光线就漏 | 每个弱工具补到 100+ 张 |
| 目标太小 | 摄像头离得远，工具占像素少；nano 模型对小目标弱 | 换 `yolov8s` + 提高 `imgsz` |
| 标注质量差 | YOLO-World 自动画框画歪了 | 训练前抽查 `preview/`，删错图 |
| 置信度卡掉 | 把握低于阈值被过滤 | 适当调低 `CONFIDENCE_THRESHOLD` |

**一句话**：解决漏检 = **让训练数据 = 摄像头实际看到的画面**，然后重新训练。

> 自测哪类问题：拿漏检的工具拍张清晰特写，走"无摄像头→选本地图片"检测。
> 特写能认、摄像头不能 → 域差距，去补摄像头位置的数据；
> 连特写都不能 → 该工具训练数据不足，补图 + 查标注。

## 1. 现在的检测后端：YOLO 优先，SIFT 回退

`src/gui.py` 启动时：

1. 若存在 `data/yolo/best.pt` → 用 **YOLOv8** 检测（`YoloToolDetector`），工具清单来自 `data/yolo/class_map.json`。
2. 若没有 best.pt 或加载失败 → **回退**到旧的 **SIFT 模板匹配**（`ToolDetector`），保证界面照常能用。

界面右侧每行的数字：YOLO 模式是**置信度百分比**（如 `87%`），SIFT 模式是 RANSAC 内点数。

> 所以：**训练出新的 `best.pt` 后，重启界面即可自动生效**，无需改任何代码。

## 2. 在界面上一键训练（推荐）

运行：

```powershell
python run.py
```

点主界面的 **🎓 训练模型** 按钮，弹出训练向导，按 **①→②→③** 顺序操作。每步在**独立窗口**里跑，不卡主界面，**跑完一步再点下一步**。

### ① 📷 采集训练素材

点按钮 → 打开摄像头采集窗口（脚本 `scripts/capture_camera_dataset.py`）。

窗口聚焦时的按键：

| 按键 | 作用 |
|---|---|
| 数字 `1`–`9` | 切换当前要拍的工具（左上角显示当前工具） |
| `空格` | 手动拍一张 |
| `c` | 开/关**自动连拍**（约 4 张/秒，持续采样） |
| `q` / `ESC` | 退出，自动保存并打印统计 |

照片落到 `C:\Users\<你>\Desktop\tool_dataset\<工具名>\`，文件名带 `cam_` 前缀，**追加**到已有数据里，不覆盖旧图。

**采集要领（决定成败）**：
- 在**摄像头实际安装位置**拍，别用手机近距离拍。
- 开自动连拍后，把工具**慢慢转着摆**：换角度、换远近、换光线、偶尔被别的东西挡一角。
- **别站着不动连拍 100 张一样的**——那等于只有 1 张有效。
- 把工具尽量摆在画面中间那个蓝色取景框内（自动标注的兜底框会更准）。
- 每个弱工具（电工胶带、胎压测试仪、绝缘测试仪样本最少）补到 **100+ 张多样化**。

### ② 🏷️ 自动标注

点按钮 → 跑 `scripts/auto_label_with_yoloworld.py`，用 YOLO-World 零样本检测给采集的图**自动画框**，生成训练数据集到 `data/yolo_dataset/`，并写好 `data.yaml`。

⚠️ **务必抽查**：打开 `data/yolo_dataset/preview/` 看几十张带框预览图。AI 自动标注**会画错**，框歪/框错的图要删掉或修正——错标注会拖垮训练效果。

### ③ 🚀 开始训练

点按钮 → 跑 `scripts/train_yolo.py`：
- CPU 约 **2–6 小时**（看数据量和 CPU），**训练期间那个控制台窗口别关**。
- 训完**自动**把最佳权重复制到 `data/yolo/best.pt`，覆盖旧模型。

训练结束后，**重启 `python run.py`**，新模型即生效，点"立即检测"验证。

## 3. 命令行方式（等价，不用界面）

```powershell
python scripts/capture_camera_dataset.py        # ① 采集（可加摄像头编号，如 ... 1）
python scripts/auto_label_with_yoloworld.py     # ② 自动标注
python scripts/train_yolo.py                    # ③ 训练
python run.py                                   # 看效果
```

## 4. 想要更好的效果（可选调优）

在 `scripts/train_yolo.py` 顶部的 `TRAIN_CONFIG`：

| 改动 | 效果 | 代价 |
|---|---|---|
| `model="yolov8n.pt"` → `"yolov8s.pt"` | 小目标/无纹理工具更准 | 训练慢一些 |
| `imgsz=416` → `640` | 远景/小目标更准 | 慢、更吃内存 |
| `device="cpu"` → `device=0` | 有 N 卡时快 5-10 倍 | 需要 CUDA 环境 |
| `epochs=50` → `100` | 学得更充分 | 时间翻倍 |

检测端：`src/yolo_detector.py` 顶部 `CONFIDENCE_THRESHOLD`（默认 0.25）。漏检多可降到 0.15（误检会变多），误检多可升到 0.4。

> **数据 > 调参**：补够"摄像头实际场景"的多样化数据，收益远大于改任何参数。

## 5. 常见问题

- **点"立即检测"提示"检测器未就绪"**：还没有 `data/yolo/best.pt`，先走训练三步生成；生成前界面会自动用 SIFT 回退。
- **训练出的模型显示英文名不是中文**：`data/yolo/class_map.json` 的英文 key 必须和训练时 `data.yaml` 里的类名一字不差。
- **首次跑标注/训练很慢**：第一次会下载 YOLO-World / PyTorch 权重（几百 MB），属正常。
- **摄像头打开要等好几秒**：Windows DSHOW 后端行为，无摄像头时探测会卡 7–9 秒才失败，正常。
- **新增/减少工具种类**：改 `data/yolo/class_map.json`，并同步 `scripts/auto_label_with_yoloworld.py` 的 `FOLDER_TO_CLASS` / `CLASS_PROMPTS`，重新走采集→标注→训练。

## 6. 相关文件速查

| 文件 | 作用 |
|---|---|
| `src/gui.py` | 界面 + 检测主循环（含🎓训练按钮，YOLO 优先/SIFT 回退） |
| `src/yolo_detector.py` | YOLOv8 检测核心 |
| `src/detector.py` | SIFT 检测核心（回退方案） |
| `scripts/capture_camera_dataset.py` | 摄像头批量采集训练素材 |
| `scripts/auto_label_with_yoloworld.py` | YOLO-World 自动标注 |
| `scripts/train_yolo.py` | 训练 + 自动覆盖 best.pt |
| `data/yolo/best.pt` | 当前生效的 YOLO 模型 |
| `data/yolo/class_map.json` | 英文类名 → 中文显示名（YOLO 工具清单的权威） |
| `data/yolo_dataset/` | 自动标注产物（含 `preview/` 抽查图） |
